# あんスタ!!Music イベント計算機

## enst-lab 入力アシスト（`assist.html`）

enst-lab のイベントダイヤ計算機（[ユニット新曲](https://enst-lab.com/event.php)・[ツアー](https://enst-lab.com/event_sp.php)）への入力を代わりに行い、結果をアプリ内に表示する自分用ツールです。

下のタブバーで「スキャン／入力／結果／設定」を切り替えるアプリ風の画面です。ホーム画面に追加すると全画面のアプリとして起動します（PWA）。

1. 上部で **イベントの種類（ユニット新曲／ツアー）** と **計算方法（今のイベント／開始から）** を選ぶ
2. **スキャン**：スクショを入れて「読み取って入力する」。読み取った数字が画像の上にボタンで出るので、タップして「現在pt」などの項目を選ぶと入力されます。PASS・ホイッスルなど項目名が近くにある数字は自動で入ります。
3. **入力**：足りない数字を補う。目標は「350万にする」ボタンでワンタップ。上の円が必須項目の進み具合です。
4. 「計算する」→ **結果** タブに必要ダイヤ・残り回数・詳細が表示されます（中継サーバー未設定のときは enst-lab の結果ページを開きます）。

入力した内容と最後の計算結果はこの端末（localStorage）に保存され、ブラウザを閉じても残ります。iPhone の Safari は長期間開かないサイトのデータを消すことがあるため、ホーム画面に追加して使うのがおすすめです。

### 友達と使う

アプリのURL（https://kage893-hub.github.io/enst/assist.html ）を送るだけで使えます。「設定」→「友達にアプリを共有」からも送れます。
入力内容はそれぞれの端末にだけ保存されるので、ほかの人の入力が見えることはありません。中継サーバーも標準で入っているため、友達は何も設定しなくても結果がアプリ内に表示されます。

### 結果をアプリ内に表示する（中継サーバー）

enst-lab は他のサイトから結果ページを読み取ることを許可していないため、ブラウザだけでは結果を受け取れません。
無料の Cloudflare Workers に `worker/enst-proxy.js` を置き、中継に使います（1日10万回まで無料。自分用なら十分です）。

1. https://dash.cloudflare.com/sign-up で無料アカウントを作る
2. 左メニュー「Workers & Pages」→「作成」→「Hello World から始める」（Worker を作成）→ 名前を `enst-proxy` などにして「デプロイ」
3. 「コードを編集」を開き、中身を全部消して [`worker/enst-proxy.js`](worker/enst-proxy.js) の内容を貼り付け →「デプロイ」
4. 表示された URL（`https://enst-proxy.＜あなたの名前＞.workers.dev`）をコピー
5. `assist.js` の `DEFAULT_PROXY` をそのURLにする（またはアプリの「設定」→「中継サーバーのURL」に貼り付ける）

- 中継サーバーは `https://kage893-hub.github.io` から開いたアプリからの送信だけを受け付け、enst-lab の2つの結果ページにだけ送信します。
- 中継サーバーの動作確認：アプリで「計算する」を押して「結果」タブに必要ダイヤが出れば成功です。

### 画像読み取りの方法（設定タブで切り替え）

| 方法 | 料金 | 特徴 |
| --- | --- | --- |
| 端末内OCR（標準） | 無料 | [Tesseract.js](https://github.com/naptha/tesseract.js) をブラウザ内で実行。画像は外部に送らない。初回に読み取りデータ（数MB）をダウンロード |

次の2つの画面は、決まった位置だけを切り出し、白黒にしてから数字専用で読むので、速く（1〜2秒）正確です。

| 画面 | 読み取る項目 |
| --- | --- |
| イベント画面（右下に「累計イベントpt」） | 現在イベントpt・所持PASS |
| アイテム画面（所持アイテム） | 現在BP・お仕事チケット（上のバー）、所持ホイッスル／メガホン（右のパネルで選んでいるアイテム。名前で見分ける） |

アイテム画面の「所持 32」のような縁取りだけの白抜き文字は、縁に囲まれた白い部分だけを文字として取り出して読みます（影で「5」が「8」に見えるような読み間違いを防ぐため）。
位置は 2000×900 のスクショを基準に計算します（`assist.js` の `SCREEN_LAYOUTS`）。ゲームの画面は「16:9 の枠が収まる大きさ」に拡大縮小され、各パーツは画面の端や中央を基準に置かれるので、その仕組みに合わせて端末ごとの位置を求めます。ノッチよけの左右の余白は端末によって違うため、何通りか試して数字が欠けずに読めた位置を採用します（スマホ 2000×900・タブレット 2000×1250 で確認済み）。それ以外の画像は全体を読み、数字をタップして項目を選びます。
| Claude API | 従量課金 | 精度が高く、どの数字が何かも判断して自動入力。Anthropic の APIキーが必要（このブラウザの localStorage にだけ保存） |

### メモ

- 計算そのものは enst-lab のサーバーで行われます。enst-lab 側のフォームが変わったら `assist.js` の項目定義（`EVENT_TYPES`・`DEFAULTS`・`ENST_EVENT_FLG`）を合わせてください。
- イベント期間の判定（月末15:00〜8日21:59／15日15:00〜23日21:59）も enst-lab と同じロジックです。期間外は「開始から」で計算します。
- 「今のイベント」は開催中のイベントの種類でしか計算できません（enst-lab の仕様）。開催中でない種類を選ぶと、結果タブにその旨が表示されます。

## オフライン計算機（`index.html`）

あんスタ!!Music のイベントで、目標ptまでの **残り曲数・必要BP・必要ダイヤ** を計算する静的Webツールです。

## 使い方

`index.html` をブラウザで開くだけで動きます（ビルド不要）。GitHub Pages などにそのまま置けます。

入力内容はブラウザの localStorage に自動保存されます。

## 計算内容

| 項目 | 計算 |
| --- | --- |
| 残り曲数 | `ceil((目標pt − 現在pt) ÷ 1曲あたりpt)` |
| 必要BP | `残り曲数 × 1曲の消費BP` |
| 使えるBP | `現在BP + 終了までの自然回復BP + その他の回復見込み` |
| 自然回復BP | 残り時間 ÷ 回復間隔。1日の放置時間のうち、BPが上限に達した後の分は取りこぼしとして差し引く |
| 必要ダイヤ | `ceil(不足BP ÷ 1回の回復BP) × 1回のダイヤ数` |

ほかに、所持ダイヤを全部使った場合の到達pt、消費BP（1〜10）ごとの曲数・ダイヤ・プレイ時間の比較表も表示します。

## ゲーム仕様の初期値

画面の「ゲーム仕様の設定」から変更できます。

- BP上限: 10
- BP回復: 30分で1
- ダイヤ回復: 20ダイヤで BP10
- 1曲の所要時間: 3分
- 獲得ptは消費BPに比例（×1〜×10）
